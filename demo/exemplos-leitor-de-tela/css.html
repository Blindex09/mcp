CSS

O CSS muda o que o leitor de tela recebe (texto escondido, lista sem marcador), o que o teclado alcança (menu aberto só com mouse), o que se vê no foco, no espaçamento de texto e no movimento. Cada exemplo é medido pelo MCP.

Exemplo ruim: Foco do teclado removido

Por quê

Quem navega com Tab não vê onde está. O outline:none apaga o anel de foco e nada o substitui; a medida mostra que o :focus não muda nenhuma propriedade visível.

O que corrigir

Não remova o outline. Se o anel padrão não combina com o design, troque por um :focus-visible com contraste (anel de 2 px ou mais, com 3:1 contra o fundo).

O que o navegador entrega ao leitor de tela (medido)

- button "Comprar"

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Medida a mais (feita pelo MCP)

Contorno quando focado: none 3px rgb(0, 0, 0) 2px. Sombra quando focado: none. Propriedades que o :focus muda: border-bottom-left-radius, border-bottom-right-radius, border-end-end-radius, border-end-start-radius, border-start-end-radius, border-start-start-radius, border-top-left-radius, border-top-right-radius, outline-offset.

Código

Código copiado

<style>#foco-ruim-btn{outline:none !important}</style><button type="button" id="foco-ruim-btn">Comprar</button>

Exemplo ruim: Texto para leitor de tela escondido com display:none

Relatório (abre em nova janela)

Por quê

Quem enxerga não vê o aviso, e quem usa leitor de tela também não: display:none tira o elemento da árvore de acessibilidade. O nome do link continua só Relatório.

O que corrigir

Use a técnica de ocultar só visualmente (clip, 1 px, posição absoluta), que mantém o texto na árvore.

O que o navegador entrega ao leitor de tela (medido)

- paragraph:
  - link "Relatório":
    - /url: "#relatorio"

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Código

Código copiado

<style>.so-leitor-ruim{display:none}</style><p><a href="#relatorio">Relatório<span class="so-leitor-ruim"> (abre em nova janela)</span></a></p>

Depende do navegador, não medido aqui: Lista sem marcador e sem role

  • Sencha
  • Matcha
  • Gyokuro

Por quê

Segundo Scott O'Hara (artigo de 2019-01-12, atualizado em 2023-01-30), o Safari com VoiceOver deixa de anunciar como lista a ul com list-style:none, e o WebKit disse que a mudança é proposital. Esta medida não consegue reproduzir isso: no Chromium e no WebKit do Playwright a lista continua sendo lista (veja as duas árvores abaixo). Quem tem um Mac deve ouvir no Safari.

O que corrigir

Por precaução, acrescente role="list" na ul sem marcador. Não custa nada e vale em todos os navegadores.

O que o navegador entrega ao leitor de tela (medido)

- list:
  - listitem: Sencha
  - listitem: Matcha
  - listitem: Gyokuro

WebKit (o motor do Safari):

  - listitem: Sencha
  - listitem: Matcha
  - listitem: Gyokuro

Exemplo ruim: Submenu que só abre com o mouse (:hover)

  • Produtos
    • Chás
    • Bules

Por quê

Com o mouse o submenu aparece. Com o teclado, o submenu fica em display:none e os links de dentro não recebem foco: Chás e Bules são inalcançáveis.

O que corrigir

Mostre o submenu também com :focus-within, ou use um botão de disclosure com aria-expanded.

O que o navegador entrega ao leitor de tela (medido)

- list:
  - listitem:
    - link "Produtos":
      - /url: "#produtos"

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Medida a mais (feita pelo MCP)

Links no código: 3. Links que o Tab alcança: 1 (Produtos).

Código

Código copiado

<style>.menu-ruim{list-style:none;margin:0;padding:0}.menu-ruim ul{display:none;list-style:none;margin:0;padding:0 0 0 1rem}.menu-ruim li:hover>ul{display:block}</style><ul class="menu-ruim"><li><a href="#produtos">Produtos</a><ul><li><a href="#chas">Chás</a></li><li><a href="#bules">Bules</a></li></ul></li></ul>

Exemplo ruim: Altura fixa que corta o texto com o espaçamento do usuário

Frete grátis para todo o Brasil em compras acima de cem reais

Por quê

Quem aumenta o espaçamento entre letras, palavras e linhas (WCAG 1.4.12) vê a segunda linha cortada: a altura é fixa e o excesso fica escondido.

O que corrigir

Use min-height (ou nenhuma altura) e não esconda o excesso com overflow:hidden.

O que o navegador entrega ao leitor de tela (medido)

- paragraph: Frete grátis para todo o Brasil em compras acima de cem reais

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Medida a mais (feita pelo MCP)

Com o espaçamento do usuário (WCAG 1.4.12) 1 trecho(s) passaram a ficar cortados: 'Frete grátis para todo o Brasil em compras acima d'.

Código

Código copiado

<p style="width:34rem;max-width:100%;height:1.5em;overflow:hidden;line-height:1.5;margin:0">Frete grátis para todo o Brasil em compras acima de cem reais</p>

Exemplo ruim: Texto cinza claro sobre branco

Entrega em até cinco dias úteis

Por quê

O contraste é de cerca de 2,8 para 1; o mínimo do WCAG para texto comum é 4,5 para 1. Pessoas com baixa visão não leem.

O que corrigir

Use uma cor de texto mais escura (por exemplo #595959, perto de 7 para 1). Meça com a ferramenta de contraste do MCP.

O que o navegador entrega ao leitor de tela (medido)

- paragraph: Entrega em até cinco dias úteis

O que o axe acha (medido)

O axe achou: color-contrast (Elements must meet minimum color contrast ratio thresholds).

Código

Código copiado

<p style="color:#9a9a9a;background:#ffffff;margin:0;padding:0.5rem">Entrega em até cinco dias úteis</p>

Exemplo ruim: Animação que ignora a preferência por menos movimento

● Atualizando

Por quê

Quem pede menos movimento no sistema (prefers-reduced-motion) continua vendo o giro infinito. Para algumas pessoas isso causa náusea ou tontura.

O que corrigir

Dentro de @media (prefers-reduced-motion: reduce) desligue ou reduza a animação.

O que o navegador entrega ao leitor de tela (medido)

- paragraph: ● Atualizando

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Medida a mais (feita pelo MCP)

Com a preferência de menos movimento ligada (emulada), a animação calculada do elemento é: gira-ruim.

Código

Código copiado

<style>@keyframes gira-ruim{to{transform:rotate(360deg)}}#mov-ruim{display:inline-block;animation:gira-ruim 2s linear infinite}</style><p><span id="mov-ruim">&#9679;</span> Atualizando</p>
