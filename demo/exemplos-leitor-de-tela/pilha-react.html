O framework não faz acessibilidade por você: o que muda é onde cada um esconde o erro.

Exemplo ruim: Acordeão em React: como não fazer

Por quê

O clique funciona só com o mouse. A div não recebe foco, não é anunciada como botão e não diz se está aberta ou fechada. O JSX compila onClick numa div sem nenhum aviso; só um linter como eslint-plugin-jsx-a11y reclama, e só se estiver configurado.

O que corrigir

Troque a div por button e mantenha aria-expanded igual ao estado do componente.

O que o navegador entrega ao leitor de tela (medido)

- text: Prazo de entrega

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Comportamento com o teclado (sonda disclosure, medido)

NÃO cumpriu: o gatilho recebe o foco do teclado. Observado: nenhum elemento (corpo da pagina).
NÃO cumpriu: estado aberto/fechado exposto (aria-expanded no botao ou <summary> de <details>). Observado: aria-expanded=None.
NÃO cumpriu: Enter alterna o estado do botao e o conteudo controlado. Observado: expanded None->None; conteudo visivel None->None.
NÃO cumpriu: o foco continua no botao. Observado: nenhum elemento (corpo da pagina).
NÃO cumpriu: Space alterna o estado do botao e o conteudo controlado. Observado: expanded None->None; conteudo visivel None->None.
NÃO cumpriu: o foco continua no botao. Observado: nenhum elemento (corpo da pagina).

Código

Código copiado

function AcordeaoRuim({ k }) {
  const [aberto, setAberto] = useState(false);
  // div com onClick: sem papel, sem foco, sem Enter/Espaço e sem estado.
  return (
    <div>
      <div id={`${k}-gatilho`} className="fake-botao" onClick={() => setAberto(!aberto)}>Prazo de entrega</div>
      {aberto && <p id={`${k}-painel`}>Cinco dias úteis.</p>}
    </div>
  );
}

Por quê

Um button com aria-expanded e aria-controls: o leitor de tela anuncia botão, recolhido ou expandido, e Enter e Espaço alternam.

O que corrigir

Nada a corrigir.

- button "Prazo de entrega"

O que o axe acha (medido)

cumpriu: Space alterna o estado do botao e o conteudo controlado. Observado: expanded false->true; conteudo visivel False->True.

Código

Código copiado

function AcordeaoBom({ k }) {
  const [aberto, setAberto] = useState(false);
  return (
    <div>
      <button type="button" id={`${k}-gatilho`} aria-expanded={aberto} aria-controls={`${k}-painel`} onClick={() => setAberto(!aberto)}>
        Prazo de entrega
      </button>
      <div id={`${k}-painel`} hidden={!aberto}><p>Cinco dias úteis.</p></div>
    </div>
  );
}

Exemplo ruim: Diálogo em React: como não fazer

Por quê

Para quem vê, abriu uma janela. Para o teclado e o leitor de tela, não é um diálogo: sem papel, sem nome, o foco fica no botão de trás e o Escape não fecha. Renderizar a caixa com {aberto && ...} é o jeito mais comum e o mais frágil. No bom, o ref chama showModal().

O que corrigir

Use dialog com showModal() em vez de renderizar uma caixa condicional, e ligue o nome ao título com aria-labelledby.

O que o navegador entrega ao leitor de tela (medido)

- button "Excluir projeto"

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Comportamento com o teclado (sonda dialog, medido)

cumpriu: o gatilho recebe o foco do teclado. Observado: button 'Excluir projeto'.
NÃO cumpriu: Enter no gatilho abre um dialogo visivel. Observado: nenhum dialogo (papel dialog/alertdialog ou <dialog open>) visivel depois do Enter.

Código

Código copiado

function DialogoRuim({ k }) {
  const [aberto, setAberto] = useState(false);
  // Aparece na tela, mas não é um diálogo: sem papel, sem nome, sem foco, sem Escape.
  return (
    <div>
      <button type="button" id={`${k}-gatilho`} onClick={() => setAberto(true)}>Excluir projeto</button>
      {aberto && (
        <div className="caixa-falsa">
          <p>Excluir este projeto?</p>
          <button type="button" onClick={() => setAberto(false)}>Cancelar</button>
        </div>
      )}
    </div>
  );
}

Exemplo bom: Diálogo em React: como fazer

Por quê

O elemento dialog aberto com showModal() dá papel, nome (pelo título), foco preso, Escape e devolução do foco ao botão.

O que corrigir

Nada a corrigir.

O que o navegador entrega ao leitor de tela (medido)

- button "Excluir projeto"

O que o axe acha (medido)

O axe não achou nenhuma violação (nível AA).

Comportamento com o teclado (sonda dialog, medido)

cumpriu: o gatilho recebe o foco do teclado. Observado: button 'Excluir projeto'.
cumpriu: Enter no gatilho abre um dialogo visivel. Observado: abriu <dialog> role=None.
cumpriu: o foco entra no dialogo ao abrir. Observado: dentro.
cumpriu: o dialogo tem nome (aria-label ou aria-labelledby). Observado: 'Excluir este projeto?'.
cumpriu: aria-modal=true ou <dialog> aberto com showModal(). Observado: aria-modal=None :modal=True.
cumpriu: Tab circula so entre os controles do dialogo (o foco nao vaza para a pagina). Observado: circulou dentro e voltou ao inicio em 2 Tab.
cumpriu: Escape fecha o dialogo. Observado: fechou.
cumpriu: ao fechar, o foco volta ao elemento que abriu o dialogo. Observado: button 'Excluir projeto'.

Código

Código copiado

function DialogoBom({ k }) {
  const dialogo = useRef(null);
  const titulo = useId();
  // <dialog> + showModal(): papel, foco preso, Escape e devolução do foco vêm do navegador.
  return (
    <div>
      <button type="button" id={`${k}-gatilho`} onClick={() => dialogo.current.showModal()}>Excluir projeto</button>
      <dialog ref={dialogo} aria-labelledby={titulo}>
        <h3 id={titulo}>Excluir este projeto?</h3>
        <p>Isso não pode ser desfeito.</p>
        <button type="button" onClick={() => dialogo.current.close()}>Cancelar</button>
      </dialog>
    </div>
  );
}

Exemplo ruim: Erro de formulário em React: como não fazer

Por quê

Aparece uma frase vermelha ao lado. O campo não é marcado como inválido, a frase não está ligada a ele, o foco não se move e nada é anunciado. No bom, useId gera o id que liga a mensagem ao campo sem colidir com outros componentes da página.

O que corrigir

Marque o campo, ligue a mensagem, mova o foco e mantenha o elemento da mensagem sempre presente.

O que o navegador entrega ao leitor de tela (medido)

- text: E-mail
- textbox "E-mail"
- paragraph:
  - button "Enviar"

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Comportamento com o teclado (sonda form_errors, medido)

NÃO cumpriu: cada campo com erro tem aria-invalid=true. Observado: 0 de 1 marcados.
NÃO cumpriu: o texto do erro esta ligado ao campo (aria-describedby). Observado: 0 de 1 com descricao.
NÃO cumpriu: o foco vai ao primeiro campo com erro (ou a um resumo de erros). Observado: button 'Enviar'.
NÃO cumpriu: o erro e' anunciado (regiao viva, role=alert) ou recebe o foco. Observado: anuncios=[] regioes=[].

Código

Código copiado

function ErroRuim({ k }) {
  const [mensagem, setMensagem] = useState('');
  const enviar = (e) => {
    e.preventDefault();
    setMensagem(e.currentTarget.elements.email.value ? '' : 'Informe o e-mail.');
  };
  // Texto vermelho solto: o campo não é marcado, a frase não está ligada a ele, o foco não se move.
  return (
    <form noValidate onSubmit={enviar}>
      <label htmlFor={`${k}-email`}>E-mail</label>
      <input id={`${k}-email`} name="email" type="email" required /> <span className="erro-visual">{mensagem}</span>
      <p><button type="submit" id={`${k}-enviar`}>Enviar</button></p>
    </form>
  );
}

Exemplo bom: Erro de formulário em React: como fazer

Por quê

O campo recebe aria-invalid, o texto do erro fica ligado por aria-describedby e anunciado por role=alert, e o foco vai ao campo.

O que corrigir

Nada a corrigir.

O que o navegador entrega ao leitor de tela (medido)

- text: E-mail
- textbox "E-mail"
- alert
- paragraph:
  - button "Enviar"

O que o axe acha (medido)

O axe não achou nenhuma violação (nível AA).

Comportamento com o teclado (sonda form_errors, medido)

cumpriu: cada campo com erro tem aria-invalid=true. Observado: 1 de 1 marcados.
cumpriu: o texto do erro esta ligado ao campo (aria-describedby). Observado: 1 de 1 com descricao.
cumpriu: o foco vai ao primeiro campo com erro (ou a um resumo de erros). Observado: input 'E-mail'.
cumpriu: o erro e' anunciado (regiao viva, role=alert) ou recebe o foco. Observado: anuncios=['Informe o e-mail.'] regioes=['Informe o e-mail.'].

Código

Código copiado

function ErroBom({ k }) {
  const [mensagem, setMensagem] = useState('');
  const campo = useRef(null);
  const idErro = useId();
  const enviar = (e) => {
    e.preventDefault();
    if (campo.current.value) { setMensagem(''); return; }
    setMensagem('Informe o e-mail.');
    campo.current.focus(); // o foco vai ao campo com erro
  };
  return (
    <form noValidate onSubmit={enviar}>
      <label htmlFor={`${k}-email`}>E-mail</label>
      <input id={`${k}-email`} ref={campo} type="email" required aria-invalid={mensagem ? 'true' : undefined} aria-describedby={idErro} />{' '}
      <span id={idErro} className="erro-visual" role="alert">{mensagem}</span>
      <p><button type="submit" id={`${k}-enviar`}>Enviar</button></p>
    </form>
  );
}

Exemplo ruim: Mensagem de status em React: como não fazer

Por quê

A região viva só passa a existir junto com o texto. Muitos leitores de tela só falam o que muda dentro de uma região que já estava na página. O {salvo && <div role="status">} cria a região no mesmo instante do texto.

O que corrigir

Renderize a região sempre; troque só o texto dentro dela.

O que o navegador entrega ao leitor de tela (medido)

- button "Salvar"

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Comportamento com o teclado (sonda status_update, medido)

cumpriu: o gatilho recebe o foco do teclado. Observado: button 'Salvar'.
cumpriu: depois da mudanca o foco continua num elemento da pagina (nao cai no corpo). Observado: button 'Salvar'.
cumpriu: a mudanca chega a quem nao a ve: regiao viva (status, alert, aria-live) ou foco movido para o novo conteudo. Observado: anuncios=['Salvo com sucesso']; foco movido=False; conteudo novo na arvore=1 linhas.
NÃO cumpriu: a regiao viva ja estava na pagina antes de o texto mudar (inserir regiao e texto juntos nao e confiavel). Observado: a regiao nasceu junto com o texto.

Código

Código copiado

function StatusRuim({ k }) {
  const [salvo, setSalvo] = useState(false);
  // A região viva só existe quando há texto: nasce junto com a mensagem e muitos leitores de tela não falam.
  return (
    <div>
      <button type="button" id={`${k}-salvar`} onClick={() => setSalvo(true)}>Salvar</button>
      {salvo && <div role="status">Salvo com sucesso</div>}
    </div>
  );
}

Exemplo ruim: Mudança de tela em React: como não fazer

Abrir a aplicação de exemplo (ruim)

Por quê

O conteúdo vira Contato, mas o título da aba continua Início, o foco permanece no botão e não há aviso: quem usa leitor de tela não sabe que a tela mudou. Nenhum roteador de React move o foco por você. No bom, um useEffect depois da troca cuida do título e do foco.

O que corrigir

Ao trocar a tela, atualize document.title, mova o foco para o novo h1 (tabindex -1) e avise numa região de status. O framework não faz isso sozinho.

O que o navegador entrega ao leitor de tela (medido)

- paragraph:
  - link "Abrir a aplicação de exemplo (ruim)":
    - /url: react-rota-ruim.html

O que o axe acha (medido)

O axe não achou nada neste exemplo. É um problema que só aparece olhando a árvore de acessibilidade ou ouvindo com o leitor de tela.

Comportamento com o teclado (sonda route_change, medido)

NÃO cumpriu: o titulo da pagina muda com a nova tela. Observado: 'Início | Loja de chás' -> 'Início | Loja de chás'.
cumpriu: o foco nao fica perdido no corpo da pagina. Observado: button 'Contato'.
NÃO cumpriu: a troca e' perceptivel sem ver a tela: anuncio, foco movido para o novo conteudo ou carga de pagina nova. Observado: anuncio=False; foco mudou=False; mesmo documento=True.

Código

Código copiado

function RotaRuim({ k }) {
  const [tela, setTela] = useState('inicio');
  // O conteúdo troca, mas o título da aba, o foco e o aviso continuam como estavam.
  return (
    <div>
      <p><button type="button" id={`${k}-ir`} onClick={() => setTela('contato')}>Contato</button></p>
      <main>{tela === 'inicio' ? <><h1>Início</h1><p>Bem-vindo à loja de chás.</p></> : <><h1>Contato</h1><p>Escreva para contato@loja.example.</p></>}</main>
    </div>
  );
}

Exemplo bom: Mudança de tela em React: como fazer

Abrir a aplicação de exemplo (bom)

Por quê

Depois de atualizar o conteúdo, o título da aba muda, o foco vai ao novo título e há uma mensagem de status.

O que corrigir

Nada a corrigir.

O que o navegador entrega ao leitor de tela (medido)

- paragraph:
  - link "Abrir a aplicação de exemplo (bom)":
    - /url: react-rota-bom.html

O que o axe acha (medido)

O axe não achou nenhuma violação (nível AA).

Comportamento com o teclado (sonda route_change, medido)

cumpriu: o titulo da pagina muda com a nova tela. Observado: 'Início | Loja de chás' -> 'Contato | Loja de chás'.
cumpriu: o foco nao fica perdido no corpo da pagina. Observado: h1 'Contato'.
cumpriu: a troca e' perceptivel sem ver a tela: anuncio, foco movido para o novo conteudo ou carga de pagina nova. Observado: anuncio=True; foco mudou=True; mesmo documento=True.

Código

Código copiado

function RotaBom({ k }) {
  const [tela, setTela] = useState('inicio');
  const titulo = useRef(null);
  const primeira = useRef(true);
  useEffect(() => {
    if (primeira.current) { primeira.current = false; return; }
    document.title = 'Contato | Loja de chás'; // título da aba
    titulo.current.focus(); // foco no novo título
  }, [tela]);
  return (
    <div>
      <p><button type="button" id={`${k}-ir`} onClick={() => setTela('contato')}>Contato</button></p>
      <main>
        <h1 ref={titulo} tabIndex={-1}>{tela === 'inicio' ? 'Início' : 'Contato'}</h1>
        <p>{tela === 'inicio' ? 'Bem-vindo à loja de chás.' : 'Escreva para contato@loja.example.'}</p>
      </main>
      <div role="status" className="so-leitor">{tela === 'contato' ? 'Página Contato carregada' : ''}</div>
    </div>
  );
}
